## What is fine

- Mid-rail is **1.649 V**. The old DC-offset crush (waveform sitting on the
  0.8 V rail) is gone. `remove_dc()` in `tools/make_wave_table.py` did that.
- Stop is a single hard drop to ~0 V. One `start()` / `stop()`, not four
  autostart loops (those would dip to 0 V between runs).
- CF in the loud bursts is **~109 kHz**. TIM6 is therefore ~1 MHz, same as the
  earlier `tone` shot (107.6 kHz vs 107.4 kHz). A 256 kHz DAC clock would have
  moved 107 kHz down to ~27 kHz. It did not.

The first two bursts are each **195 ms** of continuous ~109 kHz, with a ~180 ms
hole between them. There is no 35 ms / 46 ms / 36 ms structure inside either
blob. That is the “merged, no space” on the analog, not only on the screenshot.

`wave_seg[]` in flash is the right cuts (35, 36, 16, 27, … ms). The source WAV
still has those calls after DC removal. The running output did not play them.

## Two reasons it looks horrible

1. **1 s/div cannot show `ref` even when `ref` is correct.** PLAN gaps are
   4–137 ms (mostly 46–69 ms). Mid-rail in the gaps stays at 1.65 V — it does
   not drop to 0 V — so the trace is one fat band.
2. **This analog is not `ref` anyway.** A 4.87 s run with 195 ms CF bursts
   matches none of `ref`, `train` (35 ms / 5 ms for 2 s), `tone` (10 s
   continuous), or `gap_*`. Default after reset is still `tone`, not `ref`.

The later part of the source file (713–1145 ms) is already dense (many 1–12 ms
gaps). Even a correct `ref` will look messy there on a slow timebase. The first
four calls should not.

## Cause, found 2026-08-29

The image was built at **-O0**. `pack_half()` produces about 0.8 Msample/s at
-O0 against the 1.0 Msample/s the DMA consumes, so a half-buffer interrupt was
missed roughly every other ring and the DMA replayed stale content. That is the
whole of it: the 4.87 s run, the 195 ms merged bursts and the sawtooth envelope
are all one underrun. Release (-O2) is mandatory, not a preference — see the
header comment in `Core/Src/main.cpp`.

A missed fill is now **counted**, not silent. `synth.cpp` catches the case where
a DMA request bit is already set when the next edge arrives, and `sync`, `stop`
and the automatic end-of-run line all report `underrun=N`. **A run that reports
anything but 0 is not evidence of anything.** That check did not exist when this
capture was taken, which is why it took a scope to find.
